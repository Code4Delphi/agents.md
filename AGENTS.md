# Instruções gerais apenas para desenvolvimento Delphi
- Adicione sempre uma `uses` por linha
- Adicione as units sempre na cláusula `uses` da interface e nunca na implementation
- Sempre que uma nova unit for criada para ser usada no projeto, ela deve ser adicionada aos arquivos `.dpr` e `.dproj`
- Ao chamar um método local, use sempre `Self.`. Por exemplo, se o método declarado tem o nome `Clear`, ao chamá-lo na mesma classe use `Self.Clear`. Mas não faça isso para componentes se o nome do TButton é `btnGravar` chame 'btnGravar.Click' e não 'Self.btnGravar.Click'
- Não use `- 1`; use sempre o método `Pred()`. Exemplo: ao invés de `for i := 1 to StringGrid1.RowCount - 1 do`, use `for i := 1 to Pred(StringGrid1.RowCount) do`
- Para variáveis locais, prefira sempre usar declaração inline. Exemplo: `var LId := Self.TextoInt(edtId);`
- Não use `begin`/`end` quando houver apenas um comando no bloco. Exemplo: ao invés de `if LCIOT.Id <= 0 then begin raise ExceptionNaoLoc.Create('CIOT nao localizado.'); end;`, use `if LCIOT.Id <= 0 then raise ExceptionNaoLoc.Create('CIOT nao localizado.');`
- Prefira sempre `.IsEmpty` para comparar com vazio (`''`). Exemplo: em vez de usar `= ''`, use `.IsEmpty`
- No caption do TGroupBox adicione sempre um espaço antes e um depois, exemplo: ` Nome `
- Para componentes do tipo TC4DMaskEdit use a propriedade `.Value` e não `.Text`
- Para retirar os espaços de um componente que possui a propriedade `Text`, não use `Edit1.Text.Trim` use `Trim(Edit1.Text)`
- Quando uma alteração adicionar novos componentes em uma tela, sempre incluir os componentes diretamente nos arquivos .dfm ou .fmx. Não criar esses componentes em tempo de execução, eles devem ser criados e configurados em tempo de designer.
- Em strings SQL no Delphi, ao comparar com vazio, use aspas duplas no SQL (`""`) em vez de escapar aspas simples com `''''`. Exemplo: use `.Add('coalesce(campo, "") = ""')` e não `.Add('coalesce(campo, '''') = ''''')`.
- Sempre que criar um form deixe a propriedade `KeyPreview` como `True` no .dfm
- Prefira os helpers de string `.ToUpper`, `.ToLower` e `.ToInteger` em vez das funções `UpperCase()`, `LowerCase()` e `StrToInt()`, respectivamente.

## Instruções para gerar descrição de commits
- Analise o .diff do Git e monte para mim uma mensagem bem estruturada das alterações. Observe apenas o arquivo solicitado e me dê uma resposta curta.

## Cuidados ao editar arquivos .dfm/.fmx
- Nunca use acentos ou caracteres não ASCII nos nomes de componentes. Exemplo: use `ckComposicao`, não `ckComposição`.
- Ao editar strings com acentos em `.dfm`/`.fmx`, use escapes Delphi completos e válidos, mantendo a aspa final. Exemplo correto: `Caption = 'Tipo opera'#231#227'o'`.
- Após editar `.dfm`/`.fmx`, valide o arquivo com o conversor do RAD Studio antes de finalizar, preferencialmente em uma cópia temporária: `convert.exe -i Caminho\Arquivo.dfm`.
